HTTP QUERY

RFC 10008 · El método que faltaba

¿Qué es HTTP QUERY?

Un nuevo método HTTP estandarizado en el RFC 10008 que combina lo mejor de los verbos existentes:

  • ✓ Es seguro (no modifica estado)
  • ✓ Es idempotente
  • ✓ Acepta body en la petición
  • ✓ Es cacheable

¿Por qué existe?

Durante años, el protocolo HTTP tenía un hueco evidente:

  • GET no tiene una semántica definida para enviar un body en la petición.
  • POST está pensado para operaciones que cambian estado, aunque solo quieras consultar.
  • QUERY resuelve ese hueco: leer con body, sin romper el contrato HTTP.

Comparativa

Propiedad GET QUERY POST
Seguro ✓ ✓ ✗
Idempotente ✓ ✓ ✗
Cacheable ✓ ✓ Limitado
Body ✗ ✓ ✓

Ejemplo HTTP

Petición de búsqueda compleja, con filtros en el body, manteniendo semántica segura:

QUERY /users HTTP/1.1
Host: api.example.com
Content-Type: application/json
Accept: application/json

{
  "role": "admin",
  "sort": "name",
  "page": 1
}

Accept-Query

El nuevo header Accept-Query permite al cliente declarar qué sintaxis de body soporta para una petición QUERY.

Accept-Query: application/json
Capacidad de negociación. El servidor puede responder con 406 Not Acceptable si la sintaxis no encaja con sus reglas, evitando suposiciones.

¿Debería usarlo?

  • 🟢 Servicios internos → Sí, úsalo ya.
  • 🟡 APIs públicas → Con fallback a GET o POST.
  • 🔴 No asumir todavía soporte universal.

Conclusión

HTTP QUERY llega para llenar un vacío histórico del protocolo: poder consultar recursos complejos sin sacrificar la semántica ni la cacheabilidad.

No esperes una explosión de adopción mañana, pero sí una curva lenta y constante. Es muy probable que durante los próximos años veamos cada vez más APIs adoptándolo para reemplazar ese clásico POST /search que tantas veces hemos terminado usando "por necesidad".
